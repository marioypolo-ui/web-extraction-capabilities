# v0.3.0 — 已验证贡献与公开前隐私检查

应用先定位、修复并验证能力缺口，中央库接收可复用实现或网站参考，再独立验证、去重和集成。
站点、网络、权限、配置和业务问题由应用处理；原因未知不自动归类为中央缺陷。

- 增加版本化贡献契约、schema、合成示例、接收/验证/合并/发布状态接口。
- 打包默认本地使用；公开前核对文件、哈希、隐私及覆盖具体内容的公开授权。正常提取和失败不自动上传使用数据。
- 独立验收使用固定可信基线、相同输入和记录级比较，贡献测试在无网络、非 root、只读挂载的 Linux 容器中执行；无后端时明确受阻，不回退宿主执行。
- 同一贡献重试去重，新增证据保留历史；自报成功、失败/跳过测试、错误样本和缺少证据不能变成已验收能力。
- 停用旧公开问题自动接收和可信作者自动合并流程。历史 Issue、证据及离线诊断接口保留，旧贡献包缺新证据时返回 `needs-evidence`。
- 列表、详情和 Bundle 格式保持兼容；发布必须等待同提交真实隔离验收通过。

维护方需要 Docker/Linux 环境才能执行独立贡献验收；普通提取不要求 Docker。
合成示例验证贡献协议，不表示任何真实网站已获验证或支持。

消费应用继续使用固定 Release 的本地副本：先检查新 Release，校验归档外 SHA256，再校验 Bundle，完成自己的同输入比较、生产验收和回滚门禁后采用。中央发布不代表应用已经升级或原生产故障已经修复。
